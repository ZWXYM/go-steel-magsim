# 电机扫描操作与轮询顺序

原扫描页在提交等待时没有锁定任务按钮，重复点击可发送两次submit；队列轮询也会重新启用正在等待响应的“检查并恢复队列”，导致两次恢复请求。后端已有任务锁和重复提交检查，原求解器没有因此被替换。本次修复页面重复请求，避免无用错误、重复导出和含混状态。

提交、仅继续未尝试牌号、完整汇总都绑定固定任务ID，在响应及随后读取结束前保持单次操作；刷新重绘仍保持禁用。同一任务不能同时执行不同动作，队列恢复与这些动作相互等待。CPU实例仍可生成独立任务和整理结果，但不提交求解或恢复执行队列。后续任务仍需单独手动提交，失败不自动重试。

读取按照发起先后和动作边界提交到页面，旧ready状态或旧读取失败不能覆盖较新的running状态或最新读取结果。最新读取失败时保留已有数据、下载和错误，暂不启用扫描动作；成功读取后恢复相应按钮。操作结果未确认会明确提示检查原记录，页面不自动重复操作。

任务准备保存实际请求的牌号与测量口径并校对返回。汇总包按来源任务核验，不能挂到另一个扫描。历史导出在等待期间也保持单次请求，档案列表刷新不能提前启用。原有结果表、波形CSV、异常原因和作者的六个优化入口保持；后端、模板、状态文件及原结果没有修改。

Node VM模拟提交POST2→1、恢复POST2→1，刷新期间按钮保持禁用；同时覆盖接续、导出、异步读取交错、CPU准备和错误恢复。真实网页只浏览三份旧扫描和已有档案，不点击提交/恢复/准备/导出。实际新原生、GPU、准备与导出均为0；4983旧文件集合及SHA保持。
