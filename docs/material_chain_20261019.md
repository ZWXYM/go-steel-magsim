# 保存材料的准备与接续

材料库现在提供“准备或接续电机分析”。选择保存材料、1或2核及周期协议后，系统核对已有副本、原生导入、分析计划和独立执行记录，只补齐缺少的 CPU 准备步骤。按钮不会启动 AEDT、提交扫描或执行求解；原生导入及转矩执行仍由各自页面手动开始一次。

接口为 `POST /api/workbench/material-motor/prepare-or-reuse`，输入为 `calibration`、`key`、可选 `cores` 和 `measurement_protocol`。CPU 预览也可使用。响应包含本次复用/新增的记录、下一步和已有分析页面链接。

## 复用与恢复

- 材料按校准记录、材料键、父库/有效库、训练/排除范围以及 AMAT/metadata 字节绑定；副本还核对模板与核数，计划核对周期协议。
- 存储级操作锁防止同时创建相同链路。重复点击或在准备阶段之间中断重开，会复用已保存步骤。准备步骤内部若留下不完整文件，保留现场并报错，不覆盖旧文件。
- 多个历史副本同时存在时，优先找到已有结果或正在运行的完整链路，避免新副本遮挡已有结果。不同核数、模板或协议有各自记录。
- 失败、过期、损坏或需处理的记录保持可见，不自动重试。已实际导入的工程可复制为分析输入；已完成结果直接打开，不重新预测或求解。

## Windows 工作进程交接修复

本机虚拟环境的 Python 启动器会创建实际 Python 子进程，两者 PID 不同。旧转矩 worker 要求队列中的启动器 PID 等于当前 PID，导致 `bhexec_b8b8c83835da` 在启动 AEDT 前停止；该失败副本保留，实际求解为0。

修复后同时核对任务 ID、随机 token、PID 和创建时间，仅允许保存的活动启动器自身或其已验证的直接子进程接管队列。接管记录保留启动器与实际 worker 身份，未知或无关进程仍被拒绝。4项 CPU 交接测试包含真实 Python 子进程，原17项模拟执行回归也通过。这些测试不计入实际 Maxwell 求解。
