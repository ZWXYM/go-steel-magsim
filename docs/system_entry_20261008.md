# 统一系统入口与电机工程筛选

## 启动

主工作区双击 `D:\Project\go-steel-thesis\start_system.cmd`。公开程序副本在安装 `requirements.txt` 后可双击 `start_system.cmd`，或运行：

```powershell
python tools/start_workbench.py --port 5001 --open-browser
```

系统首页连接微磁平台、四样品校准、材料导出、牌号扫描和电机优化。端口已有服务时，启动器核对其代码、资源目录、任务存储和模式：相同实例复用；其他版本或程序保留，新实例顺延端口。浏览器打开的是实际端口。首页显示进程启动时的代码版本，编辑文件不代表旧服务已更新。

本机根目录启动按钮已绑定本次交付记录 `work/system_entry_20261008_005642/storage`，可以直接继续使用此轮校准、扫描和筛选记录。公开副本或直接使用未指定存储的 Python 入口，默认记录为程序下的 `data/system_workbench`。原 `data/workbench` 和其他目录保留，使用 `--storage` 可选择原记录；启动器默认不自动接续旧队列。日常打开无需命令行；选择特定目录时可使用：

```powershell
python tools/start_workbench.py --root D:\Project\go-steel-thesis --storage D:\Project\go-steel-thesis\magsim\data\workbench
```

`--cpu-only` 仅限制当前窗口的原生/训练下发，校准、预测、准备、整理及工程筛选仍可使用。`--resume-queue` 明确允许启动恢复；通常在网页检查现有任务后手动恢复即可。缺少许可不会阻断 CPU 功能。

## 使用流程

1. 从首页进入材料校准，加载已有记录或勾选四个确认样品建立新校准。查看 RD/TD 原始、参考、标定及整牌号留出曲线，下载四材料包。
2. 上传其他材料原生对，选择使用全部校准或完整排除牌号后预测，下载曲线、材料与 metadata。当前 B-H 校准材料尚无独立损耗数据，不能用零损耗参数算效率。
3. 进入电机工作台，选择多个库牌号、单周期/三周期和核数，生成新任务。提交后逐案串行求解、保存官方 CSV、指标及异常；每案使用新工程和独立会话，保留原始模型和全部结果。
4. 完成后生成完整汇总包，下载逐案官方曲线、指标 CSV 和总结。旧 V8_2 final 结果可独立查看、下载，缺 CSV 和异常行仍保留。
5. 进入电机优化页面，查看原基线、插片对照、V8_1 保存榜单和六个程序入口。选一份数据集和其基准案，调整约束/权重，保存工程筛选及下载包。

也可在优化页面建立配置扫描计划：上方设置约束/权重，下方选择牌号、基准、周期和核数，点击“建立新扫描计划”后提交。后台等待该任务结束，自动验证官方指标并生成筛选包；软件重开后可继续 CPU 整理，监视器本身不提交原生求解。已有任务可“关联当前任务结果”，不重复计算。计划配置及任务定义按哈希绑定，改变配置需要另建计划。

## 复用的优化规则

原 `motor/v8_1/scripts/collect_v8_1_results.py` 采用脉动降幅、铁损降幅和效率百分点变化评分，默认权重分别为 0.60、0.30、10。原约束是相对 V6_2 脉动至少降低30%、铁损不增加、平均转矩不低于 Baseline。

网页默认复用该形式。选择 V8_1 的 `original_control` 时保留原 Baseline 转矩下限；其他基准采用当前数据集内的同一案。每次筛选保存配置、数据版本、测量口径、源文件哈希、完整排序和不满足原因。原榜单按原保存顺序展示，独立数据集分别处理，未调用旧脚本中的清理或重算流程。

新任务指标从官方 CSV 复算并核对保存值、协议及源哈希；缺 CSV、失败、异常和不完整指标保持可见，不填造分数。工程筛选可用于选择下一批候选，其科学范围随数据集记录，不宣称额外的物理认证。

## 本轮功能验证

244项软件测试通过，包括端口占用/复用、进程版本快照、CPU策略、原约束与评分、无效配置恢复、CSV变更拦截、记录重开、计划恢复、配置篡改和失败隔离。14个具有完整指标的原 V8_1 案，网页默认评分及约束与原函数逐案一致；36个旧 final 原文件及五旧扫描状态哈希保持。

新 M6 单案已从网页准备、下发至原生求解和汇总，单周期31点自动导出；48插片 CoreLoss 覆盖完整，保留原 Stator/Rotor_1。转矩1.8858847 N·m、脉动18.77347%、铁损18.73937 W、效率估计89.71590%。另一个双牌号任务验证自动串行接续：23ZDKH75成功，23ZH90在3.667ms发生原生MFS矩阵分解错误。现场及消息保留，页面显示分类和原错误下载，新汇总附带派生错误说明；没有重试失败案。两案结果已关联计划并自动生成含异常项的筛选包。

另一个在求解前建立的 M6 配置计划已实际完成：原生结束后监视器自动核对该任务的官方 CSV、套用冻结配置并生成筛选包，无需手工运行 Python 或再次点击分析。转矩1.8735372 N·m、脉动19.51755%、铁损18.002897 W、效率估计89.75582%。新建计划与关联已有任务两条入口均已通过原生结果验收。

这些是库材料的单周期工程结果。本轮尝试4案，完成3案，原生失败1案；没有新 MuMax 或训练。小型官方 CSV 与摘要可公开，完整工程、缓存和日志保留私有。异常案不会进入正常候选排名。

系统完成状态由 `docs/system_delivery_plan.md` 的功能验收决定。系统完成前论文写作、配图和排版继续暂停。
