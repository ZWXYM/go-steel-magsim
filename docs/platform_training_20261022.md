# 训练任务的提交、状态与重开

主平台的单模型训练与候选模型选择共用一项当前任务。等待提交、运行或状态尚未确认时，两种开始按钮均不会重复下发；页面显示本次固定的数据集、配置、请求标识和任务ID。修改表单不会把运行中的任务改成另一份输入。

完成后保留原算法的模型与指标展示；训练失败显示具体原因并恢复操作。轮询不重叠，临时读取失败可点击“刷新当前任务状态”。页面重开会按已存ID查询原任务；提交响应丢失时按请求标识查找，恢复过程只发GET，不自动训练。当前进程已经没有原任务时，提示核对已保存模型。浏览器禁止本地存储时，当前页仍可用，跨刷新恢复不可保证。

两个训练API在创建任务前检查JSON、数据文件、测试集比例及参数容器类型。无效输入返回400 JSON，不再留下未启动的“运行中”任务；输入文件路径在提交时固定，候选训练的输出路径也固定。原训练算法、默认模型、参数筛查及评价方法保持。

API支持可选 `request_id`（12–80位字母、数字、下划线或连字符）。同一进程收到相同标识与相同配置时返回已有任务，不重复拟合；标识对应另一份配置返回409。标识不能在进程重启后保证去重，因此重开界面只查询，不自动重新提交。旧客户端未传标识时保留原提交方式。

原程序已复现连续两次候选提交、旧完成回调覆盖新结果、失败后仍显示训练中，以及无效比例返回500但遗留一个无工作线程的任务。回归覆盖上述场景、并发重复请求、读取失败、响应丢失、页面重开和原任务消失。实际接口验收使用独立目录的极小合成数据；不是生产模型重训或材料精度实验，不改原模型、数据或电机/MuMax结果。
